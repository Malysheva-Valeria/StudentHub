# StudentHub

Автоматизована інформаційна система обліку успішності та відвідуваності студентів.
Бекенд: Python 3.11+, FastAPI, SQLite. Фронтенд: HTML, CSS, JavaScript, Chart.js.

## Запуск

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

Відкрийте http://127.0.0.1:8000 — під час першого запуску база наповнюється демо-даними.
API-документація (Swagger): http://127.0.0.1:8000/api/docs

| Логін   | Пароль     | Роль          |
|---------|------------|---------------|
| admin   | admin123   | Адміністратор |
| teacher | teacher123 | Викладач      |

## Команди

```bash
python -m app.seed                   # перестворити демо-дані (запитає підтвердження «yes»; --yes — без нього)
python -m app.create_admin           # створити адміністратора / змінити його пароль (обовʼязково для production;
                                     # пароль краще вводити на запит, а не через --password: так він не потрапить в історію команд)
pip install -r requirements-dev.txt  # залежності для тестів
pytest                               # автотести API (209 тестів)
pip install -r requirements-e2e.txt && playwright install chromium   # браузерні e2e-сценарії (див. e2e/test_browser.py)
```

## Налаштування (змінні середовища)

| Змінна | За замовчуванням | Призначення |
|--------|------------------|-------------|
| `APP_ENV` | `development` | `production` — режим для розгортання за HTTPS (див. нижче) |
| `HOST`, `PORT` | `127.0.0.1`, `8000` | адреса сервера |
| `DB_PATH` | `database/studenthub.db` | файл бази SQLite |
| `SESSION_SECRET` | генерується у `database/.session_secret` | ключ підпису cookie; **обовʼязковий у production** |
| `SEED_DEMO` | `1` | наповнити порожню базу демо-даними (лише в development; у production заборонено) |
| `APP_TIMEZONE` | `Europe/Kyiv` | часовий пояс закладу — від нього залежить «сьогодні» (на Windows потрібен пакет `tzdata`) |
| `FORWARDED_ALLOW_IPS` | не задано | IP довірених reverse-proxy; лише тоді враховується `X-Forwarded-For` |

**Режим за замовчуванням — `development`**: застосунок запускається локально по HTTP, демо-облікові записи
показуються на сторінці входу, Swagger доступний. Для розгортання на сервері задайте `APP_ENV=production`:
cookie лише через HTTPS (`Secure`), заголовок HSTS, Swagger вимкнено, демо-дані не створюються
(з `SEED_DEMO=1` сервер не стартує), `SESSION_SECRET` обовʼязковий і не коротший за 32 символи, а в журналі
зʼявляється попередження, якщо в когось лишився демо-пароль. Першого адміністратора створює
`python -m app.create_admin` (логін і пароль запитуються; пароль — щонайменше 8 символів; команда працює лише
з адміністраторами). `python -m app.seed` у production відмовляється працювати без `--force`.

Якщо базу не вдається оновити до нової версії схеми, `python run.py` завершується зрозумілим повідомленням
(зміни невдалої міграції відкочуються, дані не пошкоджуються).

## Бекенд: як влаштовано

```
app/
  main.py        збирання застосунку, middleware, маршрути сторінок
  config.py      налаштування з env
  constants.py   константи предметної області (прохідний бал 60, поріг відвідуваності 75 % тощо)
  db.py          підключення SQLite, власні SQL-функції (ulower, round1, attendance_rate, COLLATE UK)
  migrations.py  версійні міграції схеми (PRAGMA user_version); schema.sql — базова версія v1
  security.py    bcrypt, серверні сесії, обмеження частоти спроб
  deps.py        залежності FastAPI: БД, поточний користувач, права, область видимості, типи параметрів
  queries.py     спільні SQL-запити кількох роутерів (дисципліни, звʼязки група–дисципліна)
  rules.py       правила: що бачить викладач, коли можна ставити оцінку, що таке борг
  grading.py     шкала ECTS і єдині формули показників
  stats.py       дашборд, особова картка, звіти
  schemas.py     Pydantic-схеми запитів і відповідей
  create_admin.py, seed.py  консольні команди: адміністратор, демо-дані
  middleware.py  заголовки безпеки (і на 500), ліміт тіла запиту 1 МБ
  routers/       тонкі HTTP-обробники
```

Ключові правила:

- **Сесії** зберігаються на сервері (таблиця `sessions`); cookie містить лише випадковий id. Тривалість — 8 год,
  завершення після 2 год бездіяльності. Вихід, блокування користувача та зміна пароля завершують сесії негайно.
- **Вхід**: невдалі спроби за 15 хв обмежені трьома лічильниками — логін + IP (10), логін з будь-яких адрес (100),
  IP з будь-якими логінами (50); власник акаунта з іншої адреси не блокується чужим підбором. Зміна пароля —
  5 невдалих спроб, після чого всі сесії користувача завершуються.
- **Оцінки й відмітки зберігають групу** (`group_id`), у якій їх поставлено. Після переведення студента його старі
  оцінки лишаються в журналі попередньої групи (з позначкою «переведено») і не зʼявляються в новій.
  Відвʼязати від групи дисципліну, з якої в цій групі вже є оцінки/відвідуваність, не можна (409), так само
  як змінити форму контролю дисципліни, з якої вже є підсумкові оцінки.
- Записи, що перевіряються перед зміною (історія перед видаленням, унікальність, правила оцінок), виконуються
  в одній транзакції `BEGIN IMMEDIATE`; конфлікт повертає 409 з `details` на конкретному полі.
- **Оцінки та відвідуваність** можна ставити лише активним студентам групи, що вивчає дисципліну, на дату
  від зарахування до сьогодні; підсумкова оцінка має відповідати формі контролю (екзамен/залік).
  Одна оцінка на заняття (студент + дисципліна + дата + тип); масове виставлення оновлює наявні.
- **Видалення** студента, дисципліни чи користувача з історією, а також групи зі студентами повертає 409 з порадою
  (змінити статус, заблокувати, перевести студентів).
- Часткові оновлення — `PATCH` (студенти, оцінки, користувачі); групи й дисципліни — `PUT`.

## Ролі та доступ

| | Адміністратор | Викладач |
|---|---|---|
| Студенти | усі, з персональними даними, експорт CSV | лише студенти своїх груп (групи його дисциплін + групи, де він куратор); дата народження й телефон приховані, email видно (контакт для навчального процесу) |
| Групи | усі; створення, зміна, видалення | лише свої групи (інші — 404) |
| Оцінки, відвідуваність | усі дисципліни | перегляд — у своїх групах; виставлення й зміна — лише зі своїх дисциплін |
| Довідник викладачів | усі користувачі, зокрема заблоковані | лише id та ПІБ активних користувачів |
| Дисципліни | усі; створення, зміна, видалення | дисципліни своїх груп і ті, які веде (інші — 404); середній бал — по своїх студентах |
| Звіти, головна | по всьому закладу | по своїх групах |
| Користувачі | керування | недоступно |

## Захист входу

- Невдалі спроби входу за 15 хв обмежено трьома лічильниками: логін + IP — 10, логін з будь-яких адрес — 100,
  IP з будь-якими логінами — 50. Спроба рахується до перевірки пароля, тож паралельні запити ліміт не обходять.
- «Знайомий пристрій»: після вдалого входу браузер отримує підписану cookie `sh_device`. Для такого браузера
  спільні лічильники (логін, IP) не діють — зловмисник не може навмисно заблокувати вхід власнику акаунта чи всій
  мережі закладу (NAT). Ліміт «логін + IP» діє завжди.
- Залишковий ризик: під час активної атаки користувач, який входить з НОВОГО пристрою, може тимчасово (до 15 хв)
  отримати «Забагато спроб входу». Адміністратор у такому разі може змінити пароль командою `python -m app.create_admin`.
- Лічильники спроб зберігаються в памʼяті процесу: після перезапуску вони обнуляються, а кілька процесів
  (`uvicorn --workers N`) рахували б спроби окремо. Запускайте застосунок **одним процесом** (як `python run.py`) —
  для SQLite і навантаження одного закладу цього достатньо.
- За реверс-проксі (nginx тощо) обовʼязково задайте `FORWARDED_ALLOW_IPS` (адресу проксі) — інакше всі клієнти
  матимуть одну IP-адресу проксі і ділитимуть один лічильник.

## Публічний доступ з цього компʼютера

`scripts/serve-public.sh` запускає сервер у режимі production і відкриває до нього HTTPS-тунель Cloudflare
(без реєстрації). Посилання `https://….trycloudflare.com` друкується в консолі й зберігається в
`database/logs/url.txt`. Налаштування — у `database/public.env` (APP_ENV, DB_PATH, SESSION_SECRET,
`FORWARDED_ALLOW_IPS=127.0.0.1`); цей файл і `database/public-credentials.txt` у git не потрапляють.

- Застосунок доступний, лише поки скрипт працює і Мак не спить. Скрипт не дає Маку заснути через бездіяльність,
  але якщо закрити кришку без живлення, Мак усе одно засне. Після перезапуску адреса змінюється.
- Зупинити: `kill $(cat database/logs/serve.pid)`. Журнали — у `database/logs/`.
